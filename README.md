# Yet Another Translator

基于大语言模型的 BetterDiscord 翻译插件，支持自动翻译、单条翻译和发送前翻译。

## 功能介绍

- **自动翻译**：逐条翻译可见消息，随新消息和滚动自动跟进，复用已缓存的译文。
- **单条语言选择**：原文语言标签可点击，支持只修改这一条的翻译目标，或永久切换全局默认目标。
- **发送前翻译**：翻译草稿后再发送，保留回复和附件；可附带原文及目标语言的 AI 翻译标注。
- **上下文与术语**：参考频道主题、附近消息、回复原文和自定义术语表。
- **消息显示**：优先使用 Discord 消息解析器显示 Markdown；支持标题、副文本、跨空行引用、列表和代码块，并保留自定义表情、提及及默认隐藏的剧透内容。可查看原文或重新翻译。
- **手动翻译器**：输入文字、选择目标语言并复制结果。
- **多语言界面**：跟随 Discord，支持简体中文、繁体中文、英语、日语、韩语、法语、德语、西班牙语、葡萄牙语、俄语和意大利语；其他语言回退英文。

## 使用方法

### 安装与配置 LLM

1. 从[发布页面](https://github.com/vempx/Yet-Another-Translator/releases)下载插件压缩包，解压得到 `YetAnotherTranslator.plugin.js`。发布页提供 `SHA256SUMS.txt` 用于校验 ZIP；语言包已内置，无需单独安装。
2. 在 BetterDiscord 设置中打开插件文件夹，放入文件并启用。升级时替换旧插件，只保留一份插件文件。
3. 在“模型服务类型”中选择本地或在线，填写 API 基础地址、模型 ID 和所需的 API Key。本地支持服务根地址或 `/v1`；在线保留服务商给出的路径，如 `https://api.deepseek.com/v1` 或 `https://openrouter.ai/api/v1`，也可填写完整 `/chat/completions` 地址。在线接口须兼容 Chat Completions。
4. 可先点击“测试连接”，使用当前填写的配置测试而不保存。确认后点击弹窗底部“保存并关闭”；“取消”或直接关闭会丢弃本次编辑。多模型服务建议明确填写模型名称；上下文容量与最大输出长度按服务实际支持的范围设置。端口使用地址中填写的值，8080 只是默认值。

在线模式指定模型时，测试连接会发送一条简短测试消息，可能产生服务商费用，不发送聊天记录。未填写模型时，通过 `/models` 获取列表；不提供该接口的服务需填写模型 ID。API 路径可参考 [DeepSeek 文档](https://api-docs.deepseek.com/guides/multi_round_chat/)或 [OpenRouter 文档](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request)。

### 翻译消息

- 在设置或消息右键菜单中开启自动翻译。成功后显示译文，右键“查看原文”可查看原始内容；关闭自动翻译恢复原文。
- 右键消息可进行单条翻译或重新翻译。自动翻译关闭时，手动翻译保留原文。
- 设置中的默认目标语言在“保存并关闭”后应用。需要清除单条覆盖时，可先点击“应用默认语言并清除单条覆盖”，再保存。
- 点击原文语言标签，再点击语言名称，只重新翻译这一条；右侧环形箭头则永久修改全局默认目标并开启自动翻译，其他频道和重启后也生效。
- 右键打开手动翻译器，可翻译自行输入的文字。
- 译文中的标题（`#`、`##`、`###`）、副文本（`-#`）和跨段引用（`>>>`）按消息格式显示。宿主消息解析器不可用时使用兼容规则；剧透内容仍默认隐藏，点击后才显示。

### 翻译后发送

1. 点击输入框旁带字母 A 的纸飞机图标，循环切换三种状态：不亮时发送原文，紫蓝色时仅发送译文，青绿色时发送原文及译文。悬停可查看当前模式和下一次点击的操作。
2. 选择旁边的发送目标语言。它与收到消息的默认目标语言独立。
3. 输入内容后按 Enter 或点击发送，插件先翻译再提交。
4. 青绿色双语模式与设置中的“发送时附带原文”联动：按钮切换立即保存，设置修改则在“保存并关闭”后生效；关闭发送翻译后发送原文。原文和译文以空行分段，普通译文后的 AI 标注在同一行，并由插件显示为较小的灰字。代码块、引用和列表的标注保留独立分隔以保护格式。字号和灰色样式仅在安装插件的本机显示。

### 使用术语表

1. 右键频道、论坛或帖子，选择“打开自定义翻译”。
2. 在插件设置的对应版区中填写术语表 JSON 文件的完整路径。
3. 点击“检查术语表”，通过后点击“保存并关闭”。帖子未单独配置时可继承父论坛配置。

可使用仓库提供的[术语表](glossaries/README.md)，或参考[生成提示词](GLOSSARY_GENERATION_PROMPT.md)制作自己的词表。文件修改后，新翻译会读取更新；已有译文可手动重新翻译。术语配置不会自动开启自动翻译。

## 注意事项

- 设置中的“模型服务类型”可选择本地或在线。本地保持原有回环地址限制；在线支持兼容 Chat Completions 的 HTTPS API，可直接连接服务商或兼容代理。
- 消息与选中的聊天上下文会发送到配置的 LLM 服务；代理可能继续转发到上游服务。API Key 保存在 BetterDiscord 配置中，未加密。
- 收到消息的译文仅自己可见；发送翻译会把最终内容发给聊天对象，附带原文开启时也会发送原文。
- 翻译期间修改草稿、回复、频道、目标语言或发送开关，会取消本次任务。失败或超长时保留草稿，不自动发送原文。纯附件直接发送，编辑已有消息不使用发送翻译。
- 双语消息按原文、译文、分隔符和标注的总长度检查。未闭合代码、剧透标记或跨段引用等格式可能被拒绝，请调整原文后重试。
- 翻译质量取决于模型与已加载上下文；缺失的历史引用不会自动下载。重要内容请核对原文。
- 测试连接通过不代表生成一定成功，建议用短文本确认翻译可用。上下文预算是估算值，实际用量以服务返回数据为准。
- v0.9.4 已通过代码复核、124 项离线测试、真实 Markdown 库与 React 模拟 DOM 验证以及 Windows／Linux CI；尚未进行真实 Discord 界面或在线服务商现场验收。
- 升级时保留配置和术语表，不要同时启用新旧两份插件。
